# HomeLabConnect: Client UI Kit

The client (`apps/client`) builds every screen from one reusable kit, so pages look and behave the same and new modules start from ready-made pieces.

## Layout

```
apps/client/src/
├── components/
│   ├── ui/            shadcn/ui components (Radix + Tailwind v4). Lowercase file names.
│   ├── form/          FormField, TextInputField, SelectInputField, DatePicker(Field), Combobox(Field)
│   ├── data/          TablePagination, EmptyState
│   ├── layout/        PageHeader, ContentCard, PageMessage, Sidebar, DashboardLayout
│   ├── ActionsMenu.tsx      "⋯" row-actions dropdown
│   └── CopyableSecret.tsx   one-time value with a Copy button
├── feedback/          FeedbackProvider + useFeedback(): success / error / confirm dialogs
├── forms/             form helpers (toFieldErrors, handleSubmitError) and shared forms
└── lib/utils.ts       cn() for merging Tailwind classes
```

- **`components/ui/`** is generated by the shadcn CLI and then owned by us. It is the only place with **lowercase file names** (`button.tsx`, `select.tsx`), so `npx shadcn@latest add <name>` keeps working. Everything else stays PascalCase.
- Import the kit with the `@/` alias: `import { Button } from "@/components/ui/button"`.
- Theme tokens (`bg-primary`, `ring-ring`, ...) are mapped onto the brand green in `src/index.css`. Retune colours there, never per component.

### Adding a shadcn component

```bash
cd apps/client
npx shadcn@latest add <component>
```

Then give it the size scale below if it's a control. Add new dependencies with `pnpm i` as usual.

## Size scale

Every control takes `size="sm" | "md" | "lg"`, with **md as the default**. The same size lines up across controls:

| Size | Height | Use                                               |
| ---- | ------ | ------------------------------------------------- |
| `sm` | h-8    | table toolbars, filters, dense rows               |
| `md` | h-10   | forms (default)                                   |
| `lg` | h-12   | sign-in and registration, primary calls to action |

This covers `Button` (plus `icon-sm` / `icon` / `icon-lg`), `Input`, `InputGroup`, `SelectTrigger`, `Textarea`, `DatePicker` and `Combobox`. `Checkbox` and `Switch` take `sm` and `md`. `Button` also has `loading`, which shows a spinner and disables the button.

## Forms

Use the field wrappers. They wire the label, hint and error to the control for screen readers:

```tsx
<TextInputField label="Email" type="email" error={fieldErrors.email} {...} />
<SelectInputField label="Role" options={roleOptions} value={role} onValueChange={setRole} />
<DatePickerField label="Hired on" required={false} value={hiredOn} onChange={setHiredOn} />
<ComboboxField label="Procedure" options={procedures} value={id} onChange={setId} />
```

`required={false}` adds "(optional)" to the label. `DatePicker` values are ISO strings (`"2026-01-15"`, `""` for none), which is what the shared Zod schemas expect.

## Feedback: dialog or inline?

| What happened                                                                          | Where it shows                                                    |
| -------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| A single field is wrong (invalid email, email taken, wrong current password)           | **Inline**, red under that field                                  |
| The action succeeded (profile saved, staff created, password changed)                  | **Success dialog**, via `feedback.success()`                      |
| The action failed for a non-field reason (wrong credentials, server down, deactivated) | **Error dialog**, via `feedback.error()`                          |
| A risky action is about to happen (deactivate, reissue password)                       | **Confirm dialog**, via `await feedback.confirm()`                |
| A page couldn't load its data                                                          | **Inline** `Alert` on the page (it's not the result of an action) |

In a form's `catch`, call `handleSubmitError(error, { title, feedback, setFieldErrors, fieldByCode })`. It applies the first three rows of this table for you.
